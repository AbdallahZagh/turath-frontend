1. Executive Summary & Project Overview
1.1 Vision & Mission
Turath is a centralized, multi-tenant tourism, cultural heritage, and hospitality ecosystem engineered specifically for Syria. The platform connects domestic and international travelers with verified Syrian hospitality providers, cultural landmarks, historical sites, guided tours, and local experiences. By bridging fragmented offline tourism offerings into a unified digital platform, Turath streamlines discovery, reservations, and on-site cryptographic verification.
1.2 Target Scope & Operational Context
The system accommodates Syria's unique operational landscape: primarily offline or spotty mobile connectivity in historic areas, an initial cash-on-arrival transaction model, distinct administrative governorates, and rigorous verification requirements for tourism providers. The MVP incorporates five specialized provider subtypes: Hotels, Restaurants (table reservations only), Trip Agencies, Event Managers, and Independent Licensed Tour Guides.
2. User Roles, Actors & Permission Matrix (RBAC)
2.1 System Actors
Super Admin (Platform Owner): Full root-level control over the platform, provider vetting and KYC verification, commission configuration, homepage promotions merchandising, cash-on-arrival coupon catalog, system analytics, content moderation, dispute mediation, and category taxonomy management.
Service Providers (Multi-Vendor Profiles):
Hotels / Accommodations: Manage room inventories, pricing tiers, amenities, generator/utility hours, check-in/out policies.
Restaurants / Cafes: Manage table allocations, indoor/outdoor zones, smoking/non-smoking sections, and time-slotted dining reservations.
Trip Planners / Travel Agencies: Publish multi-day or single-day group tours, pickup locations, itinerary milestones, seat caps, and gear requirements.
Event Managers: Organize cultural, musical, or community events, define venue floorplans, ticket tiers, and capacity limits.
Licensed Tour Guides: Offer private guided experiences, manage hourly/daily schedules, list spoken languages, and define specialty governorates.
Tourists / End-Users: Browse heritage sites, search and filter listings, view dynamic interactive maps, make real-time bookings (optionally applying an admin-published coupon code), store digital QR vouchers in offline wallets, and submit verified reviews post-attendance.

3. Comprehensive Functional Requirements
3.1 Authentication, Identity & User Security (FR-AUTH)
FR-AUTH-01 (Multi-Channel OTP Verification): User registration and login shall support primary phone number authentication via SMS or WhatsApp OTP fallback, alongside optional Email/Password authentication.
FR-AUTH-02 (Stateless JWT Authentication): The backend shall issue secure, short-lived Access Tokens (15 min) paired with cryptographically rotated Refresh Tokens stored in secure HTTP-only cookies on Web and secure storage on Flutter.
FR-AUTH-03 (Password Lifecycle): Provide automated forgot-password reset routines utilizing single-use, time-bound reset tokens with a 10-minute expiry window.
FR-AUTH-04 (User Trust & Reliability Engine): The system shall track user attendance history. Every user initializes with a Reliability Score of 100. Confirmed check-ins maintain or boost reliability, while unexcused no-shows deduct 30 points. Users scoring below 50 lose instant-booking privileges and require manual provider acceptance.
3.2 Discovery, GIS Mapping & Attractions Directory (FR-MAP)
FR-MAP-01 (Heritage & Tourist Attractions Engine): Super Admins can publish cultural points of interest (e.g., Umayyad Mosque, Palmyra, Citadel of Aleppo, Krak des Chevaliers) with historical narratives, high-resolution photo galleries, entry fee guidelines, and opening hours.
FR-MAP-02 (Interactive Unified Exploration Map): The tourist interface (Web & Flutter) shall render an interactive map showing tourist areas, hotels, restaurants, and trip departure pins with dynamic category clustering, governorate filtering, and radius search.
FR-MAP-03 (Entity-Level Location Maps): Every detail page (Hotel, Restaurant, Trip pickup, Event venue, Guide meeting spot) must embed an interactive map pinpointing exact GPS coordinates, accompanied by turn-by-turn navigation deep links to external navigation apps.
FR-MAP-04 (Multi-Faceted Search & Filters): Filtering by Governorate, Price Range (SYP / USD equivalent), Capacity, Amenities (24/7 Electricity/Generator, High-Speed Wi-Fi, Air Conditioning), Smoking/Non-Smoking, and Accessibility options.

The code applies only if it is enabled, within its date window, and allowed for that listing / pillar / provider. Invalid, expired, or out-of-scope codes are rejected. The booking summary shows list price, discount, and the cash amount due on arrival.
3.4 QR Code Verification & Check-In Workflow (FR-QR)
FR-QR-01 (Asymmetric Cryptographic Signing): Upon booking confirmation, the backend generates an encrypted, digitally signed token embedding {booking_id, user_id, provider_id, expiry, nonce, hmac_signature}.
FR-QR-02 (Offline Wallet Rendering): The Flutter app caches the generated QR code token locally. Tourists can open their digital ticket and present the QR code without active internet connection.
FR-QR-03 (Provider Verification & Check-in): Providers scan the QR code using the integrated Flutter camera scanner or enter an alphanumeric 6-character backup pass code on the Next.js web portal. The system validates the signature, marks the booking state as CHECKED_IN / COMPLETED, logs the exact timestamp, and registers the cash payment transaction for the amount due on the voucher (including any coupon discount).
FR-QR-04 (Anti-Replay Protection): Once a QR code token is checked in, it is immediately invalidated in the database. Any duplicate scanning attempt displays a prominent red warning showing the original scan timestamp and operator identity.
3.5 Financial Ledger & Cash on Arrival (COA) Model (FR-FIN)
FR-FIN-01 (Cash on Arrival Workflow): The MVP operates on a Cash on Arrival model. When the tourist completes their check-in at the venue, the provider collects the cash amount displayed on the receipt (the coupon-discounted total when a valid code was applied at booking).
FR-FIN-02 (Automated Commission Tracking): The system automatically records the platform's commission fee (configurable per category by Super Admin) as an account receivable in the Provider Financial Ledger upon every completed booking. Commission is calculated on the collected (coupon-discounted) total, not the pre-coupon list price.
FR-FIN-03 (Periodic Settlement Thresholds): Providers receive periodic automated settlement statements. If an account's unpaid commission surpasses the established platform credit limit, automated listing suspension safeguards are triggered.
3.6 Provider Portal & Business Operations (FR-PROV)
FR-PROV-01 (Onboarding & Document Submission): Providers can register their business account, upload commercial registration, ministry licenses, identity documentation, business logo, high-resolution media galleries, and set operating hours.
FR-PROV-02 (Operational Real-Time Dashboard): Next.js web portal offering revenue metrics, upcoming guest lists, table occupation charts, historical check-ins, and cancellation logs.
FR-PROV-03 (Customer Information Access): Providers can access essential booking metadata (Tourist Name, Verified Phone Number, Party Size, Special Inquiries, and if a coupon was used: the code, discount, and cash due) while protecting user privacy from unnecessary data exposure.
3.7 Super Admin Command Center (FR-ADM)
FR-ADM-01 (Provider Approval Pipeline): Super Admin reviews submitted provider applications, verifies uploaded legal documents, and toggles status between PENDING, APPROVED, REJECTED, or SUSPENDED.
FR-ADM-02 (Platform-Wide Analytics & Intelligence): Aggregated metrics on gross bookings, completed reservations, no-show rates across cities, tourist geographic origins, top-performing attractions, and commission revenue summaries.
FR-ADM-03 (CMS & Heritage Site Editor): Rich-text and GIS mapping tools to curate the national catalog of historical destinations, cultural articles, and featured promotions (homepage / discovery spotlight merchandising: featured listings and home campaigns). Featured promotions do not change the cash amount due.
FR-ADM-04 (Coupon Catalog): Super Admin publishes cash-on-arrival coupon codes after agreeing the offer with a provider (or as a platform- / pillar-wide subsidy). Each coupon has bilingual names, a unique code, a percent or fixed SYP discount, a scope (one provider, one listing, one pillar, or the whole platform), a start/end window, optional redemption caps, and an enabled/disabled flag. Providers do not self-serve coupons in the MVP. This catalog is a separate admin page (/admin/coupons) from homepage spotlight promotions. A valid code changes the SYP printed on the voucher; it never charges a card. Commission accrues on the collected (discounted) total.
4. Non-Functional Requirements (NFR)
NFR Dimension
Specification & Acceptance Standard
 
Performance & Latency
95% of read queries served under 200ms. Search queries with geo-filtering return within 350ms. QR scan verification executes under 150ms on 3G network conditions.
Concurrency & Integrity
Strict ACID guarantees using database row-level locking and Redis distributed locks (Redlock) to eliminate overbooking during simultaneous high-volume checkout attempts.
Data Security & Privacy
All traffic enforced over TLS 1.3. Passwords hashed using Argon2id / bcrypt (work factor 12). Sensitive identity documents stored in private encrypted S3 buckets with time-limited pre-signed URLs.
Internationalization & Localization
Native dual-language support (Arabic with full Right-to-Left / RTL layout styling and English LTR). Dynamic dual-currency display (SYP and USD equivalents).
Offline Resilience
The Flutter application must store active ticket passes and receipts in encrypted local storage (Hive / SQLite) to enable display and offline verification when cell service is disconnected.

6. Relational Database Schema & Data Models
The database layer is modeled in PostgreSQL with PostGIS extensions to manage geo-coordinates and high-integrity booking transactions.
